# Direct personal demands with source and completion metadata

Marcelo clarified the outcome after the first release: requests already present in instructor WhatsApp groups must go directly into the Personal Demands form/list, without creating suggestions. The demand must identify group versus contact and retain which source/requester. He also requested date, status and agent for demand completion. “Baixar” was implemented as “dar baixa/concluir”; an optional question distinguishing this from file export was left for him, without blocking the independently authorized direct-registration work.

Implementation commit: `f882312`, branch `fix/personal-group-demand-capture`, pushed. The source-aware direct endpoint extends existing `POST /api/v1/personal/demands`. Group requests require a real monitored group and captured message reference; contact requests resolve the real contact and validate message ownership. Origin JSON is stored on the demand independently of any suggestion. A unique origin key and consistent source locking prevent identical retries and direct/accepted-capture races from creating duplicates. Several different requests in a single contact message remain separate, including same-title requests with different details.

The API records completion date and authenticated actor, not a caller-supplied agent name. Identical completion retries preserve the timestamp. Reopening clears current completion metadata but retains the audit events. Historical completion actors remain unknown where no evidence exists; this release does not fabricate them.

New Maia tools: `personal_demand_from_group`, `personal_demand_from_contact`, `personal_demands_list`, `personal_demand_set_status`. Exactly those four were added to her scoped allowlist. Her scoped skill is version 0.8.0; TOOLS.md and the operator-readable rules were synchronized. Existing contact/proposal handling remains available separately. No credentials changed; the configuration guard baseline was accepted with `--no-vault`.
